# The shop in two languages (ADR, 2026-11-01)

Balázs, 2026-11-01 17:13 and 17:20 UTC: the webshop will be Hungarian and English. Product data is not translated now. This is the
foundation: where the language lives, how texts are looked up, and what stays closed until the whole shop is translated.

## Decision

**The language is the first path segment.** Hungarian keeps today's URLs (`/hu/...`, no redirect, nothing changes for search
engines). English is `/en-hu/...`: `<language>-<country>`, the shape of the BCP 47 tag `en-HU`. The segment still goes into the
dynamic `[countryCode]` route parameter, so:

- every link built as `/${countryCode}/...` keeps the language by itself, and so does every canonical URL built the same way;
- the ISR cache key is the path, so `/hu/x` and `/en-hu/x` are two cached pages (the shop's pages answer without a cookie, see
  `middleware-suti.spec.ts`);
- everything that needs the REGION (Medusa's `getRegion`, the middleware's region map) takes the country part with
  `countryOf(segment)`; `lib/i18n/locale.ts` is the one place that splits a segment (`parseSegment`).

**Texts come from a typed dictionary** (`lib/i18n/dictionary/`): `hu.ts` is the source of the keys, `en.ts` has the same shape (a
missing key is a type error, and `dictionary.spec.ts` checks the same at run time, because `next.config.js` sets
`ignoreBuildErrors`). `translator(locale)` gives `t(key, { placeholders })`; a server component builds it from the page's
`countryCode`, a client component from `useParams().countryCode`. A key neither language has comes back as the key itself, never as
an empty string. New code uses keys; the old Hungarian literals are replaced page by page (the category page first).

**The English pages are closed until the whole shop is translated:** every response under an `en-*` segment carries
`X-Robots-Tag: noindex` (one rule, in the middleware), the sitemap lists no English URL, and the header has no language switch. A
visitor never sees a half-translated page unless they type the URL.

## The alternative, and why not

**`/hu/en/...` (the language after the country).** Rejected, for three reasons. (1) A rewrite in the middleware from `/hu/en/x` to
`/hu/x` shares the ISR cache entry of the Hungarian page: one of the two languages would be served for both. (2) Keeping the cache
keys apart needs a real route segment, which means moving the whole `[countryCode]/(main|checkout|kezdolap)` tree one level
down and touching every page file. (3) The country segment is already the shop's region switch; a language is not a second region.

**A cookie or the `Accept-Language` header.** Rejected: either makes every public page dynamic (`private, no-store`), which the
shop worked to get rid of (FE-7), and one cached page could serve both languages.

**A library (`next-intl`).** Not now: it brings its own routing and middleware, and the shop's middleware and ISR rules are
already particular. The dictionary is small, typed, and replaceable by a library later; the keys would carry over.

## Consequences, and what is left

- `<html lang>` is `hu` in the root layout, which has no route parameters; `app/[countryCode]/layout.tsx` sets it to `en` after
  hydration (`HtmlLang`). The full answer is to split the root layout by language: a separate change.
- A page that is not translated yet shows its Hungarian text under `/en-hu/...` (still `noindex`). Translated so far: the
  technical category page (`modules/categories/templates/commerce/*`), the sort labels and the add-to-cart button's states, and
  (2026-11-01, second change) the header and the footer: the info bar, search, menu labels and cards, account, cart and its
  dropdown, the mobile menu, the footer columns and links, the newsletter row, the opening-hours and rights lines. The live-animal
  category template, the cart, the checkout, the account pages and the server messages (`addToCart`'s notes, form
  errors) are next, one page per change.
- The cache tag, `generateStaticParams` and the sitemap list Hungarian segments only; English pages are built on demand.

## Texts another system stores (the header and footer)

The header texts (info bar, search placeholder, menu labels, cards) and the footer (columns, link labels, newsletter row) are
edited in the OS, and the OS editor writes the Hungarian defaults back into the saved record. So "the OS sent nothing" cannot tell
a default from an edit. The rule instead: **the English shop translates a text only when it is exactly one of the known Hungarian
defaults** (`knownText(locale, group, text)`, groups `headerText`, `footerText`, `newsletter` in the dictionary), and shows a text
somebody changed as written, because the OS editor has no per-language fields yet. `ismert-szovegek.spec.ts` keeps those groups equal
to the catalogue (`modules/kezdolap/szovegek.ts`), the footer link data and the newsletter defaults, so a change of a default that the
dictionary does not follow turns red instead of silently showing Hungarian in English. The built-in footer labels (`hivatkozasok.ts`)
carry a dictionary key and do not go through this lookup.

What stays as it is, on purpose: category names (the first five mobile-menu points, the panel columns and links), shop data (address,
phone, opening hours, the legal document pages themselves), the brand names in the footer's logo row, the sample-data marker.

## Before the English shop is opened

1. Every page and message translated (a spec lists the keys still missing per page).
2. `hreflang` alternates (`hu` <-> `en`) on each page and an English sitemap; the canonical stays each page's own.
3. The language switch in the header; `X-Robots-Tag` rule removed (or the switch made configurable).
4. Product data (titles, descriptions, categories) in English, in the OS: a separate decision (Balázs: not now).
5. ~~The newsletter consent~~ (done, `commerce-hirlevel-hozzajarulas-nyelv`): the form posts its language (`locale`), the shop records
   the consent sentence the buyer read (`DEFAULT_CONSENT_TEXT_EN` for the English form while the row holds the default; a text written
   in the OS as written), its version and the language (`consent_language`, migration `20261101220000`, older rows `hu`). A spec
   keeps the English sentence in the dictionary and the shop's constant letter for letter.
6. Per-language fields in the OS editor for the header and footer texts, and English opening hours in the shop data (`CEG`).

## How to add a text

Add the key to `hu.ts` and `en.ts` (the group is the page or part), then `t("group.key", { name })`. A text with a number or a
name carries `{placeholders}`, the same in both languages. Singular and plural are two keys (`productCountOne`, `productCount`).
